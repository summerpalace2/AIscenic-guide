2026-10-18。对应机器规则 `evidence/retrieval-annotation-20261018/rerank-adoption-policy.json`，绑定现有run-01排名和候选池。登记时已有回执为NOT_SCORED，本任务尚未收到人工标注或计算质量成绩（不推断用户本机尚未提交的文件）。本文件不改变已有排序、候选或评分器。

## 决策

默认保持hybrid，不在交互聊天中开启本地reranker。只有以下条件**全部满足**才可考虑开启；这不是上线授权，仍需Java主链验证。

1. 保留集60题的候选池全部完成人工分级，三轮齐全、池覆盖完整、没有被跳过的失败。全池无相关文档的题单列，不给虚构nDCG满分；有效可答配对至少50题、25个family，否则证据不足。
2. 唯一主要质量比较为rerank对原hybrid：先按题平均三轮，再对有效题宏平均，**nDCG@5绝对增益至少0.03**，不是相对提升3%。
3. 按同一题的nDCG@5差值计胜负平（容差1e-12）：胜题数至少为负题数2倍，且胜减负至少6题。只在共同完整题上比较，列出全部排除理由。重复运行不能当新增题。
4. 按family聚类bootstrap 10,000次、固定seed=20261018，使用Python random.Random/MT19937，在按ID排序的family列表上choices抽样。每次有放回抽取相同数量的有效family，纳入每个抽中family的全部题，计算配对题差宏平均；保留family内相关性。family按Python Unicode码点排序；区间用10,000个排序估计的nearest-rank（第250和9750个值），95%百分位区间下界严格大于0。此区间不是全国泛化或充分统计功效的保证。
5. CPU固定配置下**额外重排阶段p95不超过1秒**，且接入后的真实聊天**TTFT p95不超过5秒**。前者使用逐题rerankMs的分位数，不能把两个p95相减；后者要包括实际路由、检索、门禁、生成和BFF，不能把组件p95相加。

这些数值是事前选择的工程取舍，不是统计定理。现有CPU重排成本已经超过交互预算，故即使未来质量合格也只列为离线候选，不能仅因“提升了一点”就上线。若缺标签、区间不稳定或缺端到端测量，结论都是暂不开启。

## 标注标准与一致性

- 0：仅提景点名、只给位置或只有同类其他主体，没有回答所问属性。
- 1：确实回答部分必要内容，不把泛背景自动算部分回答。
- 2：对正确主体直接回答；明确否定也可以直接回答。
- 未判不是0。文本相关性与事实真实性分开；新规则变更必须记录原因并复核此前受影响判断。

先用两题验证“分级→导出→关闭/重开→导入”的实机流程，再开发20题、后保留60题；每次不超过一小时，结束导出。草稿自动保存只是恢复保障，导出仍是正式记录。浏览器file页面是否支持持久存储由浏览器决定，存储失败必须明显提示，不能报告假保存。

全部标完后，固定随机抽取84项（1671的5%向上取整，seed=20261018），24–48小时后用新匿名顺序再次盲标，不显示原等级。保留首轮原文件，报告精确一致率、线性序数加权kappa（权重1−|i−j|/2；期望一致率为1时kappa=null，不伪造满分）、3×3混淆表和0/正相关翻转；它反映自身标注稳定性，不冒充多人一致性。没有实际重标时不能给一致性数字，也没有创建定时提醒。
