# 城市目录发布版本防回退

本板块承接来源/热更新验收中确认的不同源目录后写旧资产问题。范围为已升级到版本门禁的程序与单个共享数据库；不引入发布平台、队列或跨数据库触发器。

## 发布合同

- 无 `catalog-release.json` 时保留原 classpath + 外置覆盖兼容模式，仅当数据库尚未启用发布版本时允许。
- 外置目录有 `catalog-release.json` 时，该目录是完整权威快照，不再混入 JAR 资源。必须包含所有需要保留的受管理城市；遗漏城市会按现有完整快照规则删除其受管理记录，不能把单城补丁当完整发布包。
- manifest 包含正整数 version，以及文件名到 SHA-256 的 files 清单；清单精确覆盖目录中全部城市 JSON。每份文件只读取一批 bytes，同时用于哈希核验与解析。
- 锁内比对并提交：旧版拒绝；同版同文件及数据幂等；同版异内容拒绝；新版相同数据只推进发布版本；新版不同数据按既有事务更新目录和 revision。任何校验失败保留既有版本、指纹和行。
- 发布工具只针对准备好的完整发布目录生成 manifest；原子发布完整目录。升级前先停止所有旧程序 refresh，部署支持门禁的程序后再启用版本。旧二进制不执行新 Java 校验，不能声称已受保护。

## 分工与退出条件

实施 A：schema、导入门禁、SQLite 回归、发布工具与操作文档。实施 B：真实 PostgreSQL 独立 JVM 不同目录时序与失败保全。审查 C：只读反例与复杂度审查。主线程统一 Maven 与隔离 PG，收集失败证据、检查硬编码并交付本地审阅候选。

退出条件：正常升级/重复发布/拒绝回退/同版变更/缺少版本/坏哈希/缺文件和额外文件/旧库迁移有行为证据；真实 PG 跨 JVM 验证；相关与全量回归通过（跳过单列）；独立审查无当前范围确定阻断；专用服务清理；不操作共享业务数据，不提交、推送或部署。
