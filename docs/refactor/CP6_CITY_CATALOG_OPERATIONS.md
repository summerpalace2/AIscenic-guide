# CP6 城市目录与热更新

> **发布模式边界：**下文“同名覆盖打包文件／删除覆盖文件后恢复打包资源／空数组覆盖”的操作**只适用于没有 `catalog-release.json`、且数据库 `release_version=0` 的旧兼容模式**。版本化发布时，外置目录是完整权威快照，少放一个城市会将其从受管目录删除；启版后无清单刷新会被拒绝。请按 [城市目录版本化发布合同](CP6_CITY_CATALOG_RELEASE_VERSION.md) 准备完整目录和版本清单，不要将单城补丁目录直接用于版本化刷新。

Java 数据库是目录权威。原重庆目录保留；`ai/src/main/resources/taxonomy/cities/` 增加北京、杭州、西安、武汉各三条经过官方来源核验的入门记录。这不是全国完整目录。

来源仅核验名称、城市与简介。坐标为空时需实时地理编码；票价、开放时间、坡度、无障碍与人流未知，不按景点类型推断。建议停留时间是规划参数，不是官方承诺。

## 运维配置

启动时导入打包目录。需要外部热更新时，在 Spring 启动参数中指定：

```text
--attractions.catalog.external-directory=<管理目录的绝对路径>
--attractions.catalog.refresh-enabled=true
--attractions.catalog.refresh-interval-ms=60000
```

默认不开启定时热刷新。在**旧兼容模式**中，外部目录中同名 JSON 覆盖打包文件；建议先写临时文件，验证后原子替换目标文件，不直接逐行修改正在读取的文件。删除外部覆盖文件会恢复同名打包资源，不表示删除该打包城市；需要删除城市条目时以空数组覆盖该文件。版本化模式须另建完整发布目录并生成 manifest，不适用这些增量覆盖步骤。

每个文件是景点数组，必需字段为 `id`、`name`、`city`、`category`、`sourceUrl`、`verifiedAt`。以现有城市资产为格式示例。ID 必须唯一，不能跨城市迁移；来源须为 HTTP(S) URL，日期不能在未来，坐标若提供须合法。整个批次校验后在事务中安装；失败保留旧目录，不侵占手动录入记录。

目录修订号仅在实际内容变化时递增。聊天/规划别名消费者按修订号重载。生产 BFF 每次向 Java 查询目录，浏览器通过刷新按钮或切换城市获取最新数据。测试替身目录在 BFF 仓库 `server/data/cities/`，只在 stub 启动时加载，不能作为生产目录来源。

## 验收边界

SQLite 定向回归验证导入、坏批次、事务回滚、同内容跳过、别名改名/删除与城市隔离。版本化目录的 SQLite、PostgreSQL 多实例测试与发布工具验收以[版本化发布合同](CP6_CITY_CATALOG_RELEASE_VERSION.md)和对应 CP6 证据为准；进程崩溃恢复等未单独验证的场景不能由这些测试推断为通过。
