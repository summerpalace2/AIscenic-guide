## 行为与变更

`catalog-release.json` 包含正整数版本与文件 SHA-256 清单。有清单时，外置目录代表完整权威快照，不再混入不同 JAR 的资源；校验与解析使用同一批 bytes。既有 revision 行锁覆盖读取、版本比较与写入：旧版、同版异内容、启用版本后无清单均拒绝，保持数据和发布身份不变。同版同内容幂等；新版相同数据只更新发布版本，不造成数据 revision 自增。

旧数据库补充 `release_version` / `release_fingerprint`，保留原 revision 与内容指纹。旧无清单模式继续兼容，但没有启用版本防回退。发布工具只在准备好的完整目录生成不可覆盖的清单；合同见 `CP6_CITY_CATALOG_RELEASE_VERSION.md`。旧运维文档已注明适用范围，避免将单城覆盖说明用于完整发布包。

## 边界

仅支持门禁的程序执行新规则；旧二进制仍可能直接写旧资产。升级前必须先停旧程序 refresh，再启用版本发布，不能声称数据库层已约束旧程序。

完整目录必须包含所有需要保留的受管理城市，不能把单城补丁作为完整包，否则缺省城市按既有快照规则删除受管理记录；手工/其他来源行仍由既有所有权规则保护。

目录整体须原子发布，工具生成清单不等于切换运行实例，也不修改真实数据库。内容回滚需用更高版本重新发布。本轮未注入发布事务进程崩溃，也未验证 Linux 生产滚动部署、全国完整资产或持久队列。
