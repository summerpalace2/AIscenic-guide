# 知识索引持久重试与进程恢复

本板块承接真实 Qdrant 验收中保留的 afterCommit 内存队列丢任务问题。以 kb_document 作为持久工作记录，不新增消息中间件或通用任务框架。

## 合同

- 上传/创建、正文编辑、城市范围变更、手动刷新、归档和清空正文，与该修订的 TEXT/FILE/DELETE 意图原子持久化。不能在数据库提交后才登记唯一任务。
- 统一 claim、prepare、publish/finish、失败退避协议。领取使用数据库锁、租约 token 和修订号；昂贵准备在锁外，发布及终态写入在锁内再次核验。过期任务可接手，旧 worker 不得覆盖新修订或新 token 的终态。
- 文件上传后编辑正文按 TEXT，手动刷新有原始文件时按 FILE；不能在重启后仅从 file_url 猜任务类型。跨实例文件恢复需要共享可读上传存储。
- 先提交 SQL 新修订/归档及工作意图，再清理旧向量或重建；利用现有 SQL 可见性门禁隐藏旧/归档代，收口提前删除向量的旁路。
- 恢复任务有有界批次与失败退避，尊重 runtime syncEnabled。调度默认关闭，显式配置后才运行。mode 为空的 seed/历史 pending 不自动加入收费索引；旧资料通过手动同步明确入队。
- 不承诺外部调用 exactly-once；租约超时、未知调用结果可能重复准备/幂等发布，必须说明租约与耗时的边界。文件物理清理如未纳入持久处理，不宣称其崩溃恢复。

## 验收

实施 A 负责生产协议/schema/job/config/单测，B 负责真实 PostgreSQL/Qdrant 独立 JVM 探针，C 只读审查，主线程统一运行。使用专用 loopback 服务、随机 schema/collection、本地 embedding/rerank，不读取业务 env 或调用收费供应商。

必须实际终止已领取任务的 worker，再由另一 JVM 接手；覆盖双实例领取、失败退避、旧 lease 对新修订/归档的拒绝，以及 FILE/TEXT 语义和 seed 不自动索引。实际 SQL/Qdrant 结果与默认全量回归分别计数，跳过不算通过。独审无当前范围确定阻断后整理本地审阅候选，停止专用服务并保留证据；不提交、推送或部署。
