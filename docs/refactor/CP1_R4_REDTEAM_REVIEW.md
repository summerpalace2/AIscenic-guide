# CP1-R4 red-team review

Date: 2026-10-09

## Verdict

**PASS for the frozen CP1 candidate's reviewed single-node/application contract, with explicit infrastructure limits.** The R4 candidate closes the R3 future-createdAt and exact-expiry findings, retains deterministic coverage for the earlier intra-process races, and adds the critical delete-failure sequence across repository and service reconstruction. The test proves that a proposal with an epoch known to be current before cancellation cannot mutate the database after a new service instance is created, even though a new repository can read the stale snapshot from the shared Redis mock. No blocking defect was found in the requested review scope.

This is not a live Redis or multi-node acceptance: Redis is mocked, and the bounded local tombstone is only a same-process read guard. The application epoch check is the separate reconstruction guard. Syntactically malformed JSON is caught in production code but does not have a dedicated test case.
