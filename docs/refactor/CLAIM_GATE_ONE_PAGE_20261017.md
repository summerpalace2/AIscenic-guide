# 证据门禁：一页项目说明

要解决的问题：旅游助手即便找到了同城资料，也可能回答资料没有说明的政策，或把公告当现场保证。另一种极端是整问拒绝，连有据部分也不回答。

我做的取舍：模型理解问题，Java控制结论。把规则说明、个人资格、公告、现场状态和未来保证分成独立结论；引用必须来自原文且主体对应。能答的部分给出来源，不能答的部分保留未知，普通陪聊另走非事实通道。目录身份仅证明名称对应，不证明政策。

失败推动了什么变化：规则门禁在未见题上11/12误放；语义二元门禁降低误放却严重误拒；结论级门禁解决“只能整问二选一”。V5又暴露已核验别名信息漏传、把“没说明”当支持、复杂资格分支不稳定，以及评分器无法对齐同主体多属性。本轮分别修信息流、结构化证据状态和保守资格范围，不再加词表。自动评分无法判断的项交给真实用户裁决，AI复核不冒充人工。

工程测量：V5三轮180题次，321次逻辑调用，SDK返回327176 token，平均每题次约1.78次调用、1817.6 token；事实题链路p95为3.44/3.49/3.62秒。供应商错误0不代表生产零失败；这是预选合成证据测试，不是完整检索或浏览器首字延迟。DeepSeek默认思考模式会忽略温度，本轮门禁显式关闭思考模式后请求0温度，普通聊天配置不变。

诚实的结果：V5原始未通过结论保持不变，其误放7/7/7、误拒9/10/9混有对齐歧义，不能宣传成真实错误率。用户已逐条确认8条歧义裁决。V6三轮经用户确认12项裁决，真实误放0/0/0、误拒0/1/2，达到事先约定的收尾标准；316次调用、377350 token，p95为3.63—4.01秒。题集曾因评测城市夹具错误试跑失效，修正后的数据只当回归/稳定性证据，不宣称完全未见泛化。门禁到此结束，结构化输出误拒等限制公开。

仍有边界：静态资料不证明现场或未来；只支持清晰合取的个人资格，替代分支保守未知；模型仍可能抽错主体或误判蕴含，Java不是形式化语义证明。接下来的优先级是模型不可用时多轮追问回退，旧基线1/5需要先在当前代码复测，不能直接当当前结果。
