# CP6 语音格式与生命周期补充验收

日期：2026-10-16。结论：本轮确定缺口已修，实施自查、独立只读审查、根线程实际验证完成；仅本地审阅，未提交、推送或部署。

## 范围与修复

语音产品入口及基础回环在 2026-10-12 已完成，本轮开始时漏看历史记录，核对后改为增量复审，不作为首次实现重复报功。

1. ASR 此前只验 MIME/base64/体积，却向供应商固定声明 WAV/16kHz/mono。现在遍历 RIFF chunks，核验 PCM16、16kHz、单声道、byteRate/blockAlign、完整长度、非空数据及最长60秒；支持额外辅助 chunk 和奇数 padding。拒绝非法音频后不调用网关。
2. TTS 由 GET 查询参数改为表单 POST，避免编码后的长文本撑大 URL；百度适配器在获取 token 之前按原文小于1024 GBK字节校验。通用应用层2000字符仍是产品安全上限，不承诺2000汉字均可合成，也未引入分段队列。超出供应商容量返回413并提示缩短内容。
3. Worklet complete 已包含尾帧，控制器不再要求第二次 flush；墙钟 stop 与 complete 竞争时释放已有等待，保留取消与旧操作隔离。Node无ACK模型能复现旧路径失败，但根线程真实 Chrome 对照旧、新逻辑均通过，不能声称修复了已实证的 Chrome 60秒故障。浏览器短cap注入仅验证相同终止分支，不是实际等待60秒。
4. 补 pagehide→cancel，释放录音和播放资源。旧验收报告提到 pagehide，但当前源码此前没有该监听；本轮才补齐，保留历史差异。
5. 复用既有真实回环脚本，移除个人仓库/JDK路径和固定服务端口，改显式参数、随机端口、仅加载百度两个凭据、临时SQLite和空env。Chrome先启动再调用供应商；浏览器关闭异常不跳过服务清理；报告不包含文本、令牌或密钥。

供应商合同核对：[百度短文本REST](https://ai.baidu.com/ai-doc/SPEECH/mlbxh7xie)、[百度Java SDK](https://ai.baidu.com/ai-doc/SPEECH/Zlbxhfedg)。百度允许并推荐tex双重URL编码。独审最初只基于Spring重编码判bug，根线程对照百度合同后撤回该结论；没有盲目改成单次编码。新本地HTTP测试确认中文、空格、加号、百分号等双解码后保真。

## 独立审查与硬编码

实施与独审分离，根线程统一构建和供应商调用。最终独审确认WAV额外块/截断/长度边界、complete/flush/cancel竞态、POST双编码及外呼前容量校验无新增确定阻断问题；独审未运行Maven或供应商，实际结果由根线程提供。

规划静态扫描124个Java文件，0命中。全后端扫描359个Java、22资源、18个JSON/JSONL校验通过；仍报5个Windows系统字体候选路径，位于两个PDF基础设施适配器，源码还提供Linux/macOS或内建字体fallback。这些是既有平台字体探测字面量，本轮未改，也不把该扫描说成全工程0硬编码。本轮没有新增写死城市、景点、食物或地理坐标；音频协议采样率和供应商容量属于接口合同。

## 保留边界

未验证物理麦克风/扬声器、移动浏览器、真实连续60秒设备录音或广泛ASR准确率。真实回环不是浏览器UI经真实麦克风到供应商的端到端验收。未实现长回复自动分段，供应商短文本上限仍有效。全国完整资产、Linux生产拓扑和远程发布仍未完成；不因本轮通过宣称整个系统无bug。
