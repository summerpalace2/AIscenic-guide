# CP5 代码复杂度复核（2026-10-12）

本轮在继续 CP6 前，由 Java 与 BFF/前端两名只读子智能体分别审查，再由主执行者核对调用链、修改并验证。仅处理有明确行为后果或重复来源的代码；原有提案并发锁和代际保护由竞态回归覆盖，本轮未删。

## 已确认并处理

- Java 正式行程 Open 补偿删除只核对版本和同步修订号。ACK 不改变两者，迟到的 DELETE 可删除已确认会话。应用层增加 `OPEN_PENDING` 检查，仓储 DELETE 同时以状态作原子条件；旧匿名身份的变更也加上所有者 CAS 条件。
- Java 规划会话读取重复五份列名与映射，并把损坏的行程 JSON 静默变成空行程。合并 SELECT/映射，行程快照损坏时显式报错；兼容约束读取仍保持原处理。
- 加站时名称匹配和偏好候选读取全城市目录。现在按行程城市取目录，无城市时不凭全局目录猜地点。
- BFF 用本地 JSON 清单判断 `/api/explore` 城市是否受支持，但实际景点由 Java 返回。现由 Java 返回的未筛选目录判断，移除误导性的 `supportedCities` 契约与该路径上的深拷贝。
- 前端探索页有两份筛选/空态渲染、重复城市状态写入，切城时会短暂显示旧城市卡片。现共用渲染函数，切城即清空旧目录并忽略迟到响应，分类按钮随新目录刷新。
