# 盲标操作：先试跑，再开发集，最后保留集

使用新版 `evidence/retrieval-annotation-20261018/pool-02/annotation.html`。原pool-01和历史排名原封保留；新版保留同一候选池和正文身份，不重跑模型、不改等级，已有正式导出可以导入续标。

## 第一步：两题实机试跑

1. 用浏览器打开新版页面，默认只显示开发集。选择两题，逐篇分级，填写实际复核者姓名和必要理由。
2. 导出JSON，确认浏览器中确实有文件。只有确认文件已经保存，才使用页面上的保存确认按钮；发起下载不代表保存成功。
3. 关闭页面、重新打开，检查本地草稿恢复；再导入刚才的JSON，检查等级、理由、姓名与口径备注都在。不要删除正式文件。
4. 若草稿存储被浏览器禁止、配额不足或版本损坏，页面会告警并保留内存编辑，不能相信它已经自动保存。这时先导出文件，确认保存后再离开。不同浏览器或file页面的存储范围可能不同，导出才是可迁移记录。

脚本测试不能代替这一步的真实浏览器下载/恢复确认。不会让智能体的模拟等级冒充人工评分。

## 第二步：开发20题

开发集实际为20题、430个候选判断；保留集为60题、1241个判断。取消“只显示开发题”后可查看全80题，筛选不删除其他题已有判断，正式导出包含整个池。

用页面“全局标注口径”记录歧义裁决。例如：

- 提到景点但没回答属性：0；不是1。
- 回答部分必要属性：1。
- 正确主体且直接回答（含明确否定）：2。
- 别名/主馆/分馆拿不准：保持未判并记录理由，不猜。

口径变更后检查已标题中受影响判断，工具不会自动重写旧等级。每次最多一小时，结束必须导出。不要打开私有映射或方法排名辅助决定等级。

## 第三步：保留60题与一致性检查

标准稳定后继续保留集。指标按开发/保留分别报，不在保留集上调融合参数。未判为null、不是0，不能靠批量填0凑完整覆盖。

全部完成后，保留首轮原始导出。预先固定的84个重标样本存于私有清单，第一次标注时不应查看；24–48小时后再给新匿名顺序、隐藏原等级，重标后计算一致率、线性加权kappa及混淆表。现在只固定样本与规则，尚未执行重标或计算任何一致性数值，没有创建提醒。

质量评分与rerank采用门槛见[事前规则](RERANK_ADOPTION_RULE_20261018.md)。额外重排延迟与端到端TTFT是两个门槛，不能相加两个p95推断实际首字延迟。

本地草稿不是正式人审凭据；复核者姓名也只是自述。导出后提供文件路径，才能计算本次池化指标、逐题配对和后续采用判断。
