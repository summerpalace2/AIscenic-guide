# CP2 red-team and compatibility review

Date: 2026-10-09

## Verdict

**PASS for the reviewed preview/use-case and HTTP compatibility scope; no blocking defect found.** The frozen CP2 implementation routes both preview endpoints through the same application use case, leaves the domain preview/continuation policy in the existing service, and maps business outcomes back to the legacy HTTP status/body contract. Preview persistence writes proposals only; it does not update the session trip/revision. Apply and conversation-reset/cancel behavior remain delegated to the existing service paths.

The main evidence limitation is that tests are mostly service/controller-level, not JSON-to-HTTP MockMvc/browser tests. Wire preservation for unusual JSON values is confirmed by unchanged DTO binding and shallow map copies, rather than a complete serialized request/response matrix.

## Remaining test gap, not a blocker

Add a focused MockMvc/JSON contract matrix before a later public wire refactor: omit/null/false/empty values for `baseRevision`, `message`, `context.resetConversation`, and token fields; include unknown request and nested trip keys; assert exact response body preservation for null/false/empty/unknown keys. The existing implementation does not appear to drop these values along the CP2 path, but the current test suite does not exercise Spring's JSON binding/serialization end to end.
