# scenic-guide：Gemini 指引核查与修复

核查项目：`D:/scenic-guide`。任务开始时已有 9 个修改中的生产文件与多份未跟踪资源/测试；本次在当前工作区继续修复，未回滚原有修改、未提交或推送。

## 判断

Gemini 指出了真实的职责混杂、错误城市兜底、固定餐次插入和测试假阳性问题，改造方向部分正确。但其“14 处精确罪证、全量已通过、100% 权威、0 硬编码全国泛化”的表述缺少可信证据，方案不能原样照做。清单行号也不对应当前已进行中的修改。

- 高德分类是实体属性证据，不是旅游适用性或营业状态的保证。`14xxxx` 包含博物馆、美术馆、图书馆、科技馆、天文馆等；全部排除会误伤。`110106` 是公园内部设施，不能因为属于 `11` 就必定推荐。`05` 餐饮类别也不说明午餐供应、价格、菜单或无障碍条件。
- LLM 结构化抽取有帮助，但有超时、低置信度、格式错误和语义错误。应在服务器解析、验证并允许澄清/降级，不能把前端结果直接当业务权威。禁止所有 Java 正则不合理，时间、坐标、JSON 安全校验及兼容降级仍需要确定性规则。
- “经纬度均值”“凸包质心”“球面质心”是不同算法。城市附近点的均值可作搜索锚点；跨度大时锚定最近有效站点是启发式，不保证陆地可达。实际路线仍要核验。
- 午晚餐时段区间本身是业务策略；问题是强插固定时刻且忽略占用、交通和餐厅营业时间。需要检查完整餐长与两侧交通，不能挪动已确定的游览安排掩盖冲突。
- 类路径 JSON 只是外置资源，不自动支持热更新；接口声明也不自动完成依赖倒置。必须接入真实消费者、验证配置、原子替换快照并保留失败时的旧配置。

官方依据：[高德 POI 分类编码下载](https://a.amap.com/lbs/static/code_resource/Amap_poicode.zip)、[POI 搜索文档](https://developer.amap.com/api/webservice/guide/api/search/)、[地理编码文档](https://lbs.amap.com/api/webservice/guide/api/georegeo)。

## 额外修复的实际回归

`PoiCategoryPolicyRegistry` 曾把 `11xxxx` 景点错误映射为交通，现更正；编码优先于带“午餐”的酒店名称等文本信号。规划器未知/未安装城市策略改用通用策略，非重庆区县不会全部被当成远郊过滤。高德网关传递当前目的城市，天气城市名称动态解析为行政编码。

另修复了生产入口的跨城回退泄漏：普通外地请求以及动态检索无结果时，都不会再生成重庆目录行程。已有 41 条重庆景点资产补充明确城市字段；当地目录缺失时返回空草案及 `CITY_CATALOG_UNAVAILABLE`，覆盖率为零。已有重庆模板限定在重庆使用，尚未建设全国景点目录。

初始餐饮插入不再越过当天第一项活动的开始边界；指定区域的餐饮问答不会借用另一区域的旧锚点；文教建筑不会只因为名称含“馆”被当成餐厅。结构化餐饮的操作和餐次也不再被长句中的旧问答、地标和“早/午/晚”线索覆盖。

餐饮查询不再用店名哈希编造价格和招牌菜，不把查询到 POI 等同于在营、高分或适老。未找到实体使用待确认状态；指定菜系搜索失败不再放宽成不相关餐厅，指定店名不会被替换成泛火锅搜索。餐饮节点与出发接驳不再伪造固定交通数据，路线估算和已核验数据分开标注。

## 配置与运行边界

- 新契约：`cuisineOrPlace`、三态 `genericDiningCraving`、`timeSlot`；兼容 `cuisine_or_place`、`generic_dining_craving`、`is_generic_craving`、`time_window` 字段。LLM 输出类型与餐次值校验，泛需求清除旧的具体门店 ID。
- `TaxonomyPort` 为生产消费者提供品牌、风味、餐次区间、城市早餐配置。`PLANNER_TAXONOMY_DIRECTORY` 指定外部目录；使用时最多每五秒重新读取，失败保留上次有效快照。相关资源文件应一起发布，避免暂时混用版本。
- `PLANNER_LLM_INTENT_ENABLED` 仍沿用现有部署开关；没有启用/没有可用模型时走确定性降级，不能承诺任意生僻菜名都能识别。没有开启生产调用或部署。
- 城市名称识别通过 `TaxonomyPort` 读取 `city_names.json`，包含官方 2026-01-07 名称参考表中的 694 个市名，只保存名称、不缓存行政编码或坐标。歧义多城市请求要求澄清，明确请求字段可覆盖；这仍是有限离线提示，无法完整理解起点、目的地与菜系地名的语义角色。未指定城市时保留外置的产品默认策略。
- 景点别名在 matcher 初始化时加载，并未伪称已接入餐饮配置热更新。
- 本次采用行政中心 POI 动态查询与局部均值搜索锚点；没有实现全国水系 GIS 或凸包球面质心。通用地形策略不等于已掌握武汉水系，这些都不应该由测试空断言证明。
